Ficha prática: manuseamento de conteúdos em repositórios GitHub

Programação Web Avançada · Mestrado em Engenharia Informática e Tecnologia Web

  1. O que são operações de “Commit”, “Push” e “Pop” efetuadas num repositório?

    • Commit: regista no repositório local um conjunto de alterações (snapshot), com autor, data e mensagem, que passa a fazer parte do histórico.
    • Push: envia os commits locais para o repositório remoto (ex.: GitHub).
    • Pop: no enunciado corresponde ao pull, que traz os commits do remoto e os integra no ramo local (git pull = git fetch + git merge). Em Git existe ainda o git stash pop, que reaplica alterações guardadas temporariamente com git stash.

  2. Quais são as vantagens de usar Branchs num repositório git?

    Os branches permitem desenvolver funcionalidades, correções ou experiências de forma isolada, sem afetar o ramo principal (main). As principais vantagens são:

    • trabalho em paralelo de várias pessoas;
    • revisão de código através de pull requests;
    • integração controlada das alterações;
    • se algo correr mal, basta descartar o branch: o main mantém-se estável e pronto para publicar.

  3. Nos Merges de conteúdos resultantes de um “Pop” podem resultar em conflitos. Em que consistem e como podem ser resolvidos esses conflitos?

    Um conflito acontece quando as mesmas linhas de um ficheiro foram alteradas de forma diferente nos dois lados (local e remoto) e o Git não consegue decidir qual versão manter. O Git marca as zonas em conflito com <<<<<<<, ======= e >>>>>>>.

    Para resolver:

    1. editar o ficheiro, escolhendo ou combinando as versões;
    2. remover os marcadores de conflito;
    3. concluir com git add e git commit.

    Ferramentas como o VS Code ajudam a comparar e escolher. Fazer pull com frequência e commits pequenos reduz os conflitos.

  4. “Clone” e “Fork” são formas diferentes de replicar um repositório Git. Quais as diferenças entre eles?

    • Clone: cria uma cópia local do repositório, com todo o histórico, e mantém a ligação ao remoto original como origin. Serve para trabalhar nele, se houver permissão de escrita.
    • Fork: cria, no servidor (ex.: GitHub), uma cópia do repositório na conta de outro utilizador, independente do original. É usado para contribuir para projetos sem permissão de escrita: altera-se o fork e propõem-se as mudanças ao original através de um pull request.

    Normalmente, depois de fazer fork, faz-se clone do fork para trabalhar localmente.
